# Caso simulado 01: comienzo del turno médico

**Simulación para evaluar el sistema.** Los datos y personas de este caso son ficticios; no son hechos de ningún producto real.

## Pedido inicial

“Necesitamos una pantalla de inicio del dashboard para que cada médico confirme que está listo antes del primer paciente. Hagan una propuesta visual para esta semana.”

## Objetivo declarado

Reducir demoras y confusiones cuando se asigna el primer paciente del turno. La métrica disponible es el tiempo desde que recepción termina el ingreso hasta que el médico comienza la atención. No hay meta numérica acordada.

## Material disponible

- Nota de operaciones: recepción asigna paciente, consultorio y tablet al completar el ingreso. En algunas sedes el médico abre el dashboard al comenzar el turno; en otras lo abre después de llamar al primer paciente.
- Extracto de 20 incidentes recientes: 8 muestran cambios de consultorio después del ingreso; 5 mencionan un retraso en la sincronización. No está claro si ambos problemas se superponen ni cuál causa la demora.
- Comentario de una coordinadora: “Si el médico confirmara su disponibilidad antes, recepción sabría qué hacer”. Es una opinión de una persona, no una regla operativa confirmada.
- Comentario de un médico: “No quiero otro paso obligatorio al empezar; a veces veo al primer paciente antes de tocar la computadora”.
- Restricción confirmada para este ejercicio: la asignación puede cambiar después del ingreso y el sistema debe mostrar el estado actualizado o indicar que todavía no lo conoce.
- Desconocido: quién tiene autoridad para reasignar un consultorio, cuánto puede demorarse la sincronización y si existe una regla clínica sobre inicio de atención.

## Entrega esperada

Tomá una postura sobre dónde intervenir primero. Podés recomendar una pantalla, otro mecanismo, una prueba o un cambio previo en el flujo. Mostrá alternativas, crítica y descarte o revisión. Documentá la decisión provisional, los datos faltantes y la señal que la haría cambiar.
